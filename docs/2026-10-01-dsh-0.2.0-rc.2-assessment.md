# dsh 0.2.0-rc.2 适配评估（本分支）

> 本文记录 2026-10-01 对 dsh `0.2.0` 宿主线的接缝核对与本次改动范围。基线是上游 main（已含 0.1.7 适配，包版本 `0.1.7-rc.1-v0.3`，发布在 npm `latest`）。上一轮（0.1.7）的记录见 [0.1.7-rc.1 适配评估](2026-09-24-dsh-0.1.7-rc.1-assessment.md)，那是历史快照，不是现行兼容说明。本分支是 fork 提回上游的 PR，**上游 CI 与发布结论以维护者为准，本文不替上游下结论**。

0.2.0 的 RPC 接缝变更使得插件**无法同时支持 0.1.7 与 0.2.0**：私有的 `connection.register(owner, channel, handler)` 被公开的 `connection.rpc.handle(channel, handler)` 取代，handler 多一个 `peer` 参数。本次选择只支持 0.2.0 线，`0.1.7` 及更早的宿主由入口版本 guard 明确拒绝并给出升级命令。

CI 的固定宿主同步抬到 `0.2.0-rc.2`：`.github/workflows/ci.yml` 的 `plugin-check` 与 `boot` 两个 job 的 pin 都改了；插件的解析树中 `dsh-*` 包一律切到 `0.2.0-rc.2`。

## 0.2.0 相对 0.1.7 的接缝变更

`@deepseek-ai/dsh-client-connection` 的 RPC 注册面：

| 0.1.7 | 0.2.0 |
| --- | --- |
| `HostConnectionHandle` 上没有可用的公开 RPC 通道接口；服务原型上保留一个私有 `register(owner, channel, handler)` 重载，插件需要把自身注入作用域作为 owner 绕过「`rpc` getter 捕获服务自身 `ctx`，导致 `webServer` 未注入」的 cordis 守卫 | `HostConnectionHandle.rpc: HostConnectionRpc` 公开；`handle(channel, handler)` 与 `intercept(channel, matches, handler)` 都由 Connection 服务管理 `webServer` 注入，插件只需在注入作用域里调用一次 |
| RPC handler 接收 `(endpoint, payload, signal)` | RPC handler 接收 `(endpoint, payload, signal, peer)`；本插件的处理函数少声明最后一个参数，仍可赋值 |
| 通道安装需要在 effect 里执行 `owner.webServer.register(route)` 才能落地 | 通道由 Connection 自己在 effect 里完成 `webServer.register`，handler 决定的路径不再经过插件 |

`@deepseek-ai/dsh-llm` 的具名导出面在两条宿主线之间是 **+2**：0.1.7 为 63 个名字，0.2.0 为 65 个，新增 `ACCOUNT_QUOTA_EXCEEDED_CODE` 与 `projectToolUpdates`，无删除。这意味着 `test/host-compat.mjs` Block A 的具名导入交集断言在新快照下照常通过；Block E 仍然守护「被拒绝的旧宿主面能完成 ESM 链接」。

`@deepseek-ai/dsh-llm` 的 `LlmAdapter` 在 0.2.0 多出 `prepareCall(provider, model, signal)` 方法，但带有默认实现，不需要子类覆盖。`LlmRuntime.registerAdapter` / `registerConfigurableProviders` / `registerModelDiscovery` 三个方法签名未变。设置接缝（volatile Config / `settings.configure({ auto: false })`）与消息词表（tool 角色消息直通、显式拒绝 `developer` / `tool-addition` / `tool-removal` / `deferLoading`）是 0.1.7 那轮引入的，本轮沿用，不属于本轮变更。

## 关键决定

**1. 直接用 0.2.0 公开的 `connection.rpc.handle`**：0.1.7 时期的 owner 变通不再需要——它是 0.1.5 时代就存在的私有方法，到 0.1.7 仍属私有，到 0.2.0 被移除，只剩 `rpc.handle`。插件源码删掉 `as unknown as { register(...) }` 类型转换及其注释，直接：

```ts
cctx.effect(() => connection.rpc.handle('/llm-newapi', handler), '...')
```

handler 故意不声明第四个 `peer` 参数（少声明仍可赋值）；Connection 在 effect 里完成 `webServer.register`。

**2. `FakeConnection` 的 owner 责任翻转**：smoke 测试里的 `FakeConnection` 改为自行注入 `webServer`（`static inject = ['webServer']`），并在自身 `ctx` 上跑 effect；不再让插件传一个 owner。

**3. peer 范围与最低版本 guard 同步抬到 `0.2.0-rc.1`**：peer 写作 `>=0.2.0-rc.1 <0.3.0`（不接受 0.1.x），`src/index.ts` 的 `MINIMUM_DSH_VERSION` 同步设为 `0.2.0-rc.1`，构建产物里会出现新字符串（`lib/index.js` 中的 `MINIMUM_DSH_VERSION = "0.2.0-rc.1"`）。`test/host-compat.mjs` Block C 用这同一字符串生成断言正则。

**4. 被拒绝线 fixture 换到 0.1.7**：`REJECTED_SNAPSHOT_PATH` / `REJECTED_VERSION` 从 0.1.5 改为 0.1.7；`dsh-llm-0.1.7-rc.1.exports.json` 补上 `"version": "0.1.7-rc.2"` 并把 `0.1.7-rc.2` 加入 `surfaceSharedBy`，以匹配 Block C 的拒绝体取值。原 `dsh-llm-0.1.5.exports.json` 保留在仓库但不再被任何门禁引用。

## 与上轮 0.1.7 评估的差异

1. **接口变更是「通道注册」而非「配置接缝」**：0.1.7 那轮改的是 `settings.installSection` → `.volatile()` + `loader/volatile-update`；这一轮改的是私有 `connection.register(owner, …)` → 公开 `connection.rpc.handle`。两轮都是「宿主线 API 重塑，一份代码无法同时服务两条线」的形态。
2. **导出面差异只有 +2**：0.2.0 比 0.1.7 多 `ACCOUNT_QUOTA_EXCEEDED_CODE` 与 `projectToolUpdates`，无删除；0.1.7 那轮是 4 增 2 减，需要新增一张同步。
3. **测试 fixture 新增一张（按宿主线）**：`dsh-llm-0.2.0-rc.2.exports.json`，语义仍是「以宿主线为单位」。
4. **锁文件改动量更小**：本轮净 -24 条（25 条移除、1 条新增），其中 9 个 dsh 内部包与 16 个传递依赖随 0.1.7 子树一起消失，非 dsh 外部依赖未换版本；0.1.7 那轮是 50 个条目变化（含 19 个新传递依赖）。
5. **peer 下限与开发 pin 首次分离**：0.1.7 时两者相同（同线只有一个可用版本）；0.2.0 的 pin 是 `rc.2`、下限是 `rc.1`，因为两者共享同一导出面。
